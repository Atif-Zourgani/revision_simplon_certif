Installer un projet, étape par étape

python3 -m venv venv              # cree un espace isole pour les dependances de ce projet
source venv/bin/activate          # active cet espace isole
pip install wagtail               # installe Wagtail (et Django avec)
wagtail start moncentre .         # genere la structure du projet
python manage.py migrate          # cree les tables de la base de donnees
python manage.py createsuperuser  # cree votre compte admin
python manage.py runserver        # demarre le serveur local

Qu'est-ce qu'une Page Wagtail ?

Un type de page est une classe Python qui hérite de Page. Une classe vide, avec seulement pass, est une page statique : elle existe (titre, URL, statut publié/brouillon), mais son contenu est écrit en dur dans le template HTML, pas modifiable depuis l'admin.

from wagtail.models import Page

class HomePage(Page):
    pass

La rendre dynamique : ajouter des champs

Pour qu'un contenu devienne modifiable depuis l'admin, trois choses à faire ensemble, toujours dans cet ordre :

  1. Ajouter le champ au modèle (models.py).
  2. L'ajouter à content_panels via un FieldPanel (sinon il reste invisible dans l'admin, même s'il existe en base).
  3. Générer puis appliquer la migration.
from django.db import models
from wagtail.admin.panels import FieldPanel
from wagtail.fields import RichTextField
from wagtail.models import Page

class CompetencesPage(Page):
    accroche = models.CharField(max_length=255, blank=True)   # texte court
    description = RichTextField(blank=True)                   # texte riche (plusieurs paragraphes, mise en forme)

    content_panels = Page.content_panels + [
        FieldPanel("accroche"),
        FieldPanel("description"),
    ]
python manage.py makemigrations <nom_app>   # genere le fichier decrivant le changement
python manage.py migrate                     # applique le changement a la base
Piège fréquent

Oublier le FieldPanel dans content_panels : le champ existe en base mais reste invisible dans l'admin. Ou oublier le filtre |richtext dans le template sur un RichTextField : le contenu s'affiche en texte brut, balises HTML comprises.

Les types de champs les plus utilisés

ChampUsage
CharField(max_length=...)Texte court, une ligne (titre, accroche, téléphone).
TextField()Texte long sans mise en forme (adresse). Avec {{ page.adresse|linebreaks }} pour garder les retours à la ligne.
RichTextField()Plusieurs paragraphes avec mise en forme (gras, listes, liens). Toujours avec |richtext dans le template.
ForeignKey("wagtailimages.Image", ...)Une image administrable (voir plus bas).

Fichiers statiques : CSS, JS, images non administrables

Un fichier statique (CSS, JS, ou une image que personne ne doit changer depuis l'admin) est servi via la balise {% static %}. C'est un fichier sur le disque, identique pour tout le monde.

{% load static %}
<img src="{% static 'images/competences.jpg' %}" alt="Illustration de mes competences">
<link rel="stylesheet" href="{% static 'css/mysite.css' %}">

Une image administrable : pas un simple fichier

Dans Wagtail, une image modifiable depuis l'admin n'est pas un chemin de fichier : c'est un objet stocké dans la bibliothèque d'images de Wagtail. Le champ sur le modèle est donc une relation (ForeignKey) vers le modèle Image de Wagtail, pas un CharField.

photo = models.ForeignKey(
    "wagtailimages.Image",     # pointe vers la bibliotheque d'images Wagtail
    null=True,                 # peut etre vide en base
    blank=True,                # peut etre vide dans le formulaire admin
    on_delete=models.SET_NULL, # si l'image est supprimee, le champ redevient vide
    related_name="+",          # pas besoin de retrouver les pages depuis l'image
)

Dans le template, on ne peut pas se contenter d'un <img src=""> : il faut la balise {% image %}, avec une spec de redimensionnement.

{% load wagtailimages_tags %}
{% image page.photo fill-800x600 class="page-image" alt=page.photo_alt %}
Rappel accessibilité

Rendez aussi l'alt administrable (un CharField à côté du champ photo), rempli par la même personne qui choisit l'image. Voir la page Accessibilité.

Le header commun, dans base.html

Tout ce qui est écrit dans base.html, en dehors de {% block content %}, s'affiche automatiquement sur toutes les pages. C'est l'endroit pour un header unique, jamais recopié dans chaque template.

<body>
    {% wagtailuserbar %}

    <header>
        <strong>Mon site</strong>
        <nav>
            <a href="/">Accueil</a>
            <a href="/contact/">Contact</a>
        </nav>
    </header>

    {% block content %}{% endblock %}
</body>
Piège fréquent

Laisser le header copié-collé dans chaque template de page au lieu de le remonter une seule fois dans base.html : un changement doit alors être répété partout, source d'oubli et d'incohérence.
