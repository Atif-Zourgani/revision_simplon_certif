SEO et référencement

Le référencement naturel (SEO) regroupe les techniques qui aident un moteur de recherche à comprendre, indexer et classer les pages d'un site. Wagtail en fournit déjà une partie nativement, il reste à les activer et les compléter.

C7 Évaluation 2 — Cas pratique brief-seo-projet-personnel.pdf

SEO de contenu vs SEO technique

Le SEO de contenu décrit chaque page individuellement (titre, description, structure du texte). Le SEO technique concerne l'infrastructure du site dans son ensemble (sitemap, vitesse de chargement, structure du code).

1. Les champs SEO title / Search description

Google n'affiche pas forcément le titre visible sur la page : il affiche en priorité le champ SEO title, et en dessous une courte description, Search description. Sans ces champs remplis, Google compose lui-même un extrait, souvent peu lisible ou peu engageant.

Dans l'admin Wagtail, l'onglet "Promote" de chaque page contient ces deux champs. Remplissez-les sur vos pages principales, avec un texte spécifique à chaque page.

Exemple, page "Nos cours" d'un studio de yoga

SEO title : "Cours de yoga à Bordeaux, collectifs et individuels, Studio Namaste"
Search description : "Découvrez nos cours de yoga collectifs et individuels à Bordeaux. Tous niveaux, réservez votre premier cours dès maintenant."

Ce texte reprend des mots qu'un visiteur taperait probablement dans Google ("cours de yoga", "Bordeaux"), tout en restant une vraie phrase lisible, pas une liste de mots-clés empilés.

2. La hiérarchie de titres

Un moteur de recherche lit la structure HTML pour comprendre le sujet principal (<h1>) et comment le contenu se découpe (<h2>, <h3>...). Une page sans structure claire, ou avec plusieurs <h1>, est plus difficile à classer.

Un seul <h1> par page, et des niveaux suivants qui s'enchaînent sans saut (jamais un <h2> suivi directement d'un <h4>).

3. Le texte alternatif des images

Un moteur de recherche ne "voit" pas une image : il se base uniquement sur son alt pour savoir ce qu'elle représente. C'est ce texte qui permet à une image d'apparaître dans Google Images. Un alt absent ou générique ("image1") est une occasion manquée, à la fois pour le SEO et pour l'accessibilité (voir la page Accessibilité).

class CoachProfilPage(Page):
    photo = models.ForeignKey("wagtailimages.Image", null=True, blank=True, on_delete=models.SET_NULL, related_name="+")
    photo_alt = models.CharField(
        max_length=255, blank=True,
        help_text="Decrit la photo (SEO + accessibilite)",
    )

    content_panels = Page.content_panels + [
        FieldPanel("photo"),
        FieldPanel("photo_alt"),
    ]

4. Le sitemap

Un moteur de recherche découvre normalement les pages en suivant les liens d'une page à l'autre. Si une page est mal reliée, elle risque de ne jamais être découverte. Un sitemap liste explicitement toutes les URLs du site, sans dépendre des liens internes.

# settings/base.py
INSTALLED_APPS = [
    # ...
    "django.contrib.sitemaps",
    "wagtail.contrib.sitemaps",
]
# urls.py
from wagtail.contrib.sitemaps.views import sitemap

urlpatterns = [
    # ...
    path("sitemap.xml", sitemap),
]

Rechargez le serveur et ouvrez /sitemap.xml : la liste de vos pages publiées doit s'afficher, en XML, générée automatiquement depuis votre arbre de pages.

Piège fréquent

Oublier "django.contrib.sitemaps" dans INSTALLED_APPS : sans lui, Django ne trouve pas le template nécessaire, et affiche une erreur TemplateDoesNotExist.

5. Le fichier robots.txt

Avant d'explorer un site, un moteur de recherche cherche /robots.txt pour savoir ce qu'il a le droit d'explorer et où trouver le sitemap. Sans ce fichier, rien n'est bloqué par défaut, mais le point d'entrée vers le sitemap n'est pas explicite.

# urls.py
from django.http import HttpResponse

def robots_txt(request):
    content = (
        "User-agent: *\nAllow: /\nSitemap: "
        + request.build_absolute_uri("/sitemap.xml")
    )
    return HttpResponse(content, content_type="text/plain")

urlpatterns = [
    # ...
    path("robots.txt", robots_txt),
]

User-agent: * s'adresse à tous les robots, Allow: / autorise l'exploration de tout le site, Sitemap: donne l'adresse complète du fichier généré au point précédent.

6. Le poids des images

La vitesse de chargement fait partie des critères de classement, et une page lente abîme l'expérience du visiteur. Une image affichée en petit mais chargée en grand fait transférer des données jamais vues à l'écran.

7. Audit Lighthouse, catégorie SEO

Lighthouse vérifie automatiquement une partie des points vus ci-dessus (titres, meta-description, alt, taille des liens cliquables...). DevTools → onglet Lighthouse → décocher tout sauf SEO → lancer l'analyse → corriger chaque problème signalé.

8. Préparer sa justification orale

Pour chaque optimisation appliquée, une ou deux phrases expliquant pourquoi elle est pertinente pour votre projet précis, pas une explication générale du SEO. Ce texte sert de support direct pour le Cas pratique, où vous devrez argumenter ces choix face au jury.

Checklist avant l'oral

  • seo_title et search_description remplis sur les pages principales, spécifiques à chaque page
  • Un seul h1 par page, hiérarchie de titres cohérente
  • Images avec un alt pertinent
  • /sitemap.xml répond et liste les pages publiées
  • /robots.txt existe et pointe vers le sitemap
  • Poids des images maîtrisé (taille d'affichage proche de la taille réelle)
  • Audit Lighthouse SEO passé, problèmes corrigés
  • Une justification écrite pour chaque choix, prête pour l'oral
