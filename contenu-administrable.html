Contenu administrable : Snippets, listes/détail, formulaires

Trois patterns qui reviennent sur presque tous les projets : un contenu réutilisable sans URL propre (Snippet), une famille de pages identiques reliées par l'arbre (liste/détail), et un formulaire géré sans écrire de HTML de champ.

C4 C5 C6 Briefs 3d, 3e, 3f

Les Snippets

Un Snippet est un modèle de données géré dans l'admin comme une page (formulaire, liste, bouton "Ajouter"), mais qui vit à côté de l'arbre de pages, pas dedans. À utiliser quand le contenu n'a pas besoin de sa propre URL (un cours, un témoignage, une catégorie...).

from wagtail.snippets.models import register_snippet

@register_snippet
class Cours(models.Model):           # herite de models.Model, PAS de Page
    nom = models.CharField(max_length=100)
    horaire = models.CharField(max_length=100, blank=True)
    description = models.TextField(blank=True)

    panels = [                        # "panels", pas "content_panels" : un Snippet n'a pas de titre de page
        FieldPanel("nom"),
        FieldPanel("horaire"),
        FieldPanel("description"),
    ]

    def __str__(self):
        return self.nom               # sans ca, l'admin affiche "Cours object (1)"

Afficher tous les Snippets sur une page

Un template ne reçoit, par défaut, que les champs de sa propre page. Pour lui donner aussi les Snippets, on utilise get_context :

class CoursPage(Page):
    def get_context(self, request):
        context = super().get_context(request)
        context["cours_list"] = Cours.objects.all()   # tous les Cours existants en base
        return context
{% for cours in cours_list %}
    <h3>{{ cours.nom }}</h3>
    <p>{{ cours.horaire }}</p>
{% endfor %}
Piège fréquent

Créer un Snippet pour un contenu qui devrait être une vraie page (ex : la fiche d'un coach, cliquable, avec sa propre adresse). Un Snippet n'a pas d'URL : s'il faut pouvoir cliquer dessus pour arriver sur "sa" fiche, c'est une page, pas un Snippet (voir liste/détail ci-dessous).

Pages liste / détail, via l'arbre de pages

Pour une famille de fiches cliquables (une par coach, une par article...), on crée deux types de pages reliés par l'arbre : une page "liste" (parent) et des pages "détail" (enfants).

class CoachsIndexPage(Page):               # la liste
    intro = RichTextField(blank=True)

    subpage_types = ["pages.CoachProfilPage"]  # on ne peut ajouter QUE des fiches coach dessous

    def get_context(self, request):
        context = super().get_context(request)
        context["coachs"] = CoachProfilPage.objects.child_of(self).live()
        # child_of(self) : seulement les enfants de CETTE page ; .live() : seulement les publiees
        return context


class CoachProfilPage(Page):                # le detail
    specialite = models.CharField(max_length=100, blank=True)
    bio = RichTextField(blank=True)

    parent_page_types = ["pages.CoachsIndexPage"]  # ne peut etre cree QUE sous une page liste
{% for coach in coachs %}
    <a href="{% pageurl coach %}">{{ coach.title }}</a>
    {# pageurl construit l'adresse de la fiche, pas besoin de l'ecrire a la main #}
{% endfor %}

Sur la page détail, pour remonter à la liste parente :

<a href="{% pageurl page.get_parent %}">← Retour</a>
Snippet ou page liste/détail ?

Pas d'URL propre nécessaire, juste une fiche d'info réutilisable → Snippet. Besoin d'une URL cliquable, propre à chaque élément → deux pages reliées par l'arbre (subpage_types / parent_page_types).

Formulaire de contact, avec Wagtail Forms

Wagtail fournit deux briques toutes prêtes : AbstractEmailForm (la page qui contient un formulaire) et AbstractFormField (un champ de ce formulaire, créé comme donnée depuis l'admin, pas codé en dur).

from modelcluster.fields import ParentalKey
from wagtail.admin.panels import FieldPanel, InlinePanel
from wagtail.contrib.forms.models import AbstractEmailForm, AbstractFormField

class FormField(AbstractFormField):
    page = ParentalKey("ContactPage", on_delete=models.CASCADE, related_name="form_fields")


class ContactPage(AbstractEmailForm):
    intro = RichTextField(blank=True)
    thank_you_text = RichTextField(blank=True)

    content_panels = AbstractEmailForm.content_panels + [
        FieldPanel("intro"),
        InlinePanel("form_fields", label="Champs du formulaire"),
        FieldPanel("thank_you_text"),
        FieldPanel("to_address"),    # email qui recoit chaque message
        FieldPanel("from_address"),
        FieldPanel("subject"),
    ]

Les vrais champs (Nom, Email, Message) ne sont pas écrits dans le code : ils se créent depuis l'admin, via InlinePanel, sur la page Contact elle-même.

<form action="{% pageurl page %}" method="POST">
    {% csrf_token %}
    {{ form.as_p }}
    {# genere label + input de chaque champ cree dans l'admin, rien a coder #}
    <input type="submit" value="Envoyer">
</form>

Bonus automatique

Les réponses envoyées sont consultables dans l'admin (menu à trois points sur la page Contact → "Voir les réponses"), exportables en CSV, sans aucun code supplémentaire.

C6 — Hiérarchiser les contenus

L'intégration des contenus (C6) ne se limite pas à remplir des champs : elle couvre aussi l'ordre dans lequel les pages sont créées dans l'arbre, et son respect par rapport au schéma fonctionnel défini en cadrage (une fiche coach rattachée sous "Notre équipe", pas à la racine).

Piège fréquent

Créer une page au mauvais endroit de l'arbre (ex : à la racine au lieu de sous la page d'accueil) : la page existe et peut sembler fonctionner en admin, mais provoque une erreur 404 sur le site public, car un Site ne sert que le sous-arbre de sa page racine configurée.
