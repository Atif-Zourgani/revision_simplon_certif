Permissions, groupes et publication

Sur un vrai projet, on n'est jamais connecté en superutilisateur qui peut tout faire. On délègue des droits précis, limités à une partie de l'arbre, avec ou sans publication directe.

C4 Brief 3g, Partie 1

Le principe : groupes et permissions de page

On ne donne jamais un droit directement à un utilisateur : on crée un groupe ("Settings" → "Groups"), on lui attribue des permissions de page sur une ou plusieurs pages de l'arbre, puis on place les utilisateurs concernés dans ce groupe.

DroitCe qu'il permet
AddCréer de nouvelles pages sous la page choisie.
EditModifier le contenu d'une page existante (brouillon, sans le publier).
PublishRendre une modification visible sur le site public, sans validation d'un tiers.
LockVerrouiller une page pour empêcher une modification simultanée.
À retenir

Les droits cochés sur une page s'appliquent aussi à toutes les pages situées dessous dans l'arbre. Une seule ligne sur une page parente suffit à couvrir toute sa branche.

Piège fréquent

Oublier de cocher "Can access Wagtail admin" au niveau du groupe : sans elle, les membres ne peuvent même pas se connecter à l'admin, même avec des permissions de page correctement configurées.

Deux rôles possibles, une seule différence

Même geste de création pour les deux, seule la case "Publish" change :

Add / EditPublish
Groupe qui propose sans publier
(ex: "Coachs" sur Coach Max)		ouinon
Groupe qui publie directement
(ex: "Admin contenu")		ouioui

Sans "Publish" : le workflow de validation

Un utilisateur sans droit de publication ne voit pas de bouton "Publish", seulement "Submit for moderation". Ça envoie la page dans un circuit de validation, déjà configuré par défaut sur tout le site Wagtail.

  1. L'utilisateur du groupe limité modifie une page, clique "Submit for moderation".
  2. Un compte avec les droits de publication ouvre la même page : un bandeau indique qu'elle est en attente, avec des boutons "Approve"/"Reject".
  3. Après "Approve", la modification est publiée automatiquement, visible sur le site public.

Avec "Publish" : publication directe

Même parcours, mais le bouton "Publish" apparaît directement : aucune validation intermédiaire, la modification est en ligne dès l'enregistrement.

Créer le groupe et l'utilisateur, pas à pas

  1. "Settings" → "Groups" → "Add a group". Nommez-le (ex : "Coachs" ou "Admin contenu").
  2. Dans "Page permissions", ajoutez une ligne par page/branche à couvrir : choisissez la page, cochez les droits voulus (Add + Edit, avec ou sans Publish).
  3. Cochez "Can access Wagtail admin" dans les permissions générales du groupe.
  4. Enregistrez, puis "Settings" → "Users" → "Add a user" : créez le compte, cochez le groupe dans "Groups", ne cochez ni "Superuser" ni "Staff status".
  5. Testez en navigation privée : modifiez une page couverte, vérifiez le bouton affiché ("Submit for moderation" ou "Publish"), et vérifiez qu'une page hors périmètre reste invisible.
